What's solid ✓

Next.js proxy pattern is exactly right

Keeping the Bolna API key in Next.js API routes (not the browser) is the correct approach. Your BOLNA_API_KEY never leaks to the client. Good instinct.

SQLModel + SQLite is perfect for this scope

Zero setup, type-safe, and sufficient for a demo. No need for Postgres here — SQLite is honest and fast. Good call.

httpx async is the right HTTP client

Non-blocking Bolna API calls means your FastAPI won't freeze while waiting for Bolna to respond. Correct choice over requests.

10s dashboard polling as webhook backup

Smart fallback. Webhooks can miss in dev. Polling ensures the dashboard always reflects current state even if a webhook fires late or fails.

Gaps to fix before building ⚠

You're not storing the Bolna call_id — this breaks everything downstream

When Bolna triggers a call, it returns a call_id. You MUST save this to your Appointment row. Without it, you can't match incoming webhooks to appointments, can't fetch transcripts, and your dashboard will have orphaned records.

# In your Appointment model, add: call_id: Optional[str] = None call_status: str = "pending" # pending|in_progress|completed|failed transcript: Optional[str] = None # In routers/appointments.py, after Bolna API call: response = await bolna.trigger_call(appointment) appointment.call_id = response["call_id"] session.add(appointment) session.commit()

Bolna call payload needs recipient_phone_number in E.164 format

Bolna expects +91XXXXXXXXXX not 9876543210. Add a phone normaliser in your bolna.py service or the call will fail silently.

# services/bolna.py def normalise_phone(phone: str) -> str: digits = "".join(filter(str.isdigit, phone)) if len(digits) == 10: return f"+91{digits}" if len(digits) == 12 and digits.startswith("91"): return f"+{digits}" return f"+{digits}"

Webhook endpoint needs signature verification + 200 response immediately

Bolna will retry the webhook if it doesn't get a 200 within ~3 seconds. Do your DB write async and return 200 immediately. Also validate the payload has a call_id before processing.

# routers/webhooks.py @router.post("/webhook/bolna") async def bolna_webhook(payload: dict, background: BackgroundTasks): background.add_task(process_webhook, payload) return {"status": "ok"} # Return 200 instantly async def process_webhook(payload: dict): call_id = payload.get("call_id") if not call_id: return # update appointment by call_id...

Your 3 pre-build questions — answered

Bolna API key + Agent ID?

Get API key from platform.bolna.ai → Settings → API Keys. Agent ID is shown on your Apollo HealthLine agent card. Put both in .env as BOLNA_API_KEY and BOLNA_AGENT_ID.

ngrok or deploy for webhooks?

Use ngrok locally first — faster iteration. Run ngrok http 8000, paste the HTTPS URL into Bolna's webhook field as https://xxxx.ngrok.io/webhook/bolna. Deploy only when it's working.

Doctor/branch in intake form?

Keep it simple — specialty + preferred date/time is enough. Let Asha ask for doctor and branch over the call. Fewer form fields = cleaner demo and shows the voice agent doing its job.
